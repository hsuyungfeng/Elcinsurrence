## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| 假數據冒充真實輸出 | server 端點硬編碼判定/名稱，未接引擎（P0-1） | blocking | 端點必須接 `run_presubmission_check`/`build_appeal_draft`/`get_rule`；示範資料一律 `demo: true` 標記 |
| 依賴清理誤刪實際使用的包 | P1-6 移除 flask（server.py 實際 import） | blocking | 動 pyproject.toml 前 grep 全倉 import；改後 `uv sync` + 啟動冒烟 |
| 測試鎖定錯誤行為 | 斷言把 bug 寫成規格（P1-1） | advisory | 修 bug 時審查相鄰測試命名與斷言語意 |
| errorhandler 引用未定義類 | UploadFileError 在使用後定義 → server 啟動 NameError | advisory | 例外類與其 handler 一起定義於 ApiError 附近 |
| monkeypatch 打錯目標 | from-import 符號要 patch 引用者命名空間（`server.extract_text`），patch 來源模組無效 | advisory | from-import 的函式以 `monkeypatch.setattr(引用模組, ...)` 替身 |
| 「清洗」把攻擊變成合法值 | P1-3 初版先取 `os.path.basename()` 再校驗白名單，而 `basename('../etc/passwd')`＝`'passwd'` 可通過＝**攻擊被悄悄清洗成合法檔名**；且清洗使 `A/1` 與 `A_1` 收斂 → 兩案 PHI 報告互相覆寫 | blocking | 識別碼一律**校驗原始值後拒絕**，不做清洗改寫；與「系統故障必須與業務結論可區分」同源 |
| 休眠漏洞因功能上線而活化 | P1-5 原註明「硬編碼資料不觸發；CSV 匯入一上線即爆」——匯入上線後即成真實注入點，但清單狀態沒人重新評級 | advisory | **功能上線時回頭重評既有安全清單**，而非只在發現當時評一次 |
