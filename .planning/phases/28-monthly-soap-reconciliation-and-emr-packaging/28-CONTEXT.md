# Phase 28 Context: 當月申報 (TOTFA) 與本機每日門診語音 SOAP 自動比對入庫暨 11 碼標準檔名 EMR 批次打包引擎

## 一、 使用者核心需求與工作流程覆核 (Workflow Recheck)

### 1. 痛點剖析：TOTFA.zip 與日常語音 SOAP 的資料斷層
- **健保門診費用申報檔 (TOTFA.zip)**：
  - 診所於次月初（例如 2023 年 8 月初申報 `202307`）上傳至健保署的費用申報總檔。
  - 檔案內容：僅包含病患基本資料欄位、診斷代碼（`d18`, `d20-d26`）、醫令與處方藥令（`p4`, `p12` 等）以及申請總點數（`d39`）。
  - **核心限制**：**TOTFA.zip 完全不包含醫師於看診當下撰寫或口述之門診 SOAP 病歷本文**。
- **Local Server（本機伺服器）上的日常看診語音 SOAP 紀錄**：
  - 診所平時看診時，每天從月初到月底由診間專員/護理師/醫師即時錄音（Phase 24 SoapVoice / Phase 27 診間工作台），在 Local Server 上即時產生結構化 SOAP（`S/O/A/P`）與原始錄音、影像生檔。
  - 儲存索引契約：以「**醫事機構代碼 (Facility Code)** + **申報年月份 (YYYYMM / 民國 YYMM，如 202307 / 11207)** + **病患身分證號／病歷號 (ID Card / Record No)** + **門診就醫日期 (Visit Date)**」做為嚴格唯一識別鍵。
- **自動比對與入庫關聯機制 (Reconciliation & Ingest Engine)**：
  - 當院所上傳當月申報檔（例如 `202307` TOTFA.zip）時：
    - 系統在解析 TOTFA 總檔各案件時，依據每筆申報案件的身分證號、就醫日期與年月份，**自動檢索 Local Server 上日常語音紀錄庫（`PATIENT_DB`、`CaseStore` kind=`his` 及 `evidence_vault`）**。
    - 若比對成功，**自動將真實日常門診 SOAP 病歷文字（S、O、A、P）與佐證檔案路徑注入該案件之 payload 並持久化存入資料庫 (`CaseStore` kind=`monthly`)**。
    - 當案件進入**第 2 階（抽樣事前預審）**或**第 3 階（核減事後申復）**時，直接取用已關聯之真實 SOAP 病歷，供醫師與 Qwen LLM 進行支持度審查、缺口分析與申復抗辯備存。

## 二、 健保 11 碼標準檔名與 EMR 批次打包規格需求 (@emr-batch-packaging-naming-spec.md)

### 1. 11 碼標準檔名編碼邏輯
所有獨立病歷電子檔案（文字、影像、報告、附件），檔名必須精準為 11 碼半形英數字：
$$\text{檔名} = [\text{第1階層 2碼}] + [\text{第2階層 1碼}] + [\text{第3階層 2碼}] + [\text{第4階層 6碼}]$$
1. **第 1 階層代碼（醫事機構與門住診別，2 碼）**：
   - `11`：西醫基層門診（診所門診案件）
   - `12`：醫院門診
   - `15`：門診透析
2. **第 2 階層代碼（資料屬性分類，1 碼）**：
   - `A`（病歷本文）：SOAP 門診紀錄單、病歷首頁、處方箋/藥囑單、手術/麻醉紀錄。
   - `B`（檢查檢驗報告-影像類）：X 光、CT、MRI、超音波、臨床處置照片（含 DICOM 及 JPEG/PNG）。
   - `C`（檢查檢驗報告-非影像類）：血液生化檢驗報告（CBC、HbA1c）、病理組織報告、心電圖。
   - `D`（其他書類/附件類）：手術同意書、麻醉同意書、事前審查核准函、自費同意書。
3. **第 3 階層代碼（案件分類，2 碼）**：
   - `01` 一般案件、`03` 西醫門診專科、`09` 診所門診案件等（不足 2 碼左補 0）。
4. **第 4 階層代碼（案件流水號，6 碼）**：
   - 健保抽審清單之 6 碼流水號（不足 6 碼左補 0，如 `001352`）。
5. **多檔擴充規則**：同案同類別有多個檔案時，於末尾加上 `-1`, `-2`（例如 `11A09001352-1.pdf`）。

### 2. 500MB ZIP 批次封包命名與自動動態分包
1. **ZIP 封包檔名格式**：
   $$\text{ZIP檔名} = (\text{醫事機構代碼 10碼}) + \text{\_} + (\text{系統日期民國 7碼}) + \text{\_} + (\text{序號 3碼}) + \text{.zip}$$
   - 範例：`3503250461_1120701_001.zip`。
2. **動態容量裁切機制**：
   - 健保署嚴格規定一次上傳總容量上限為 500MB。
   - 引擎具備即時容量累計監控：當封包累積達 450MB 臨界值時，自動截斷並遞增序號生成第二個封包（`_002.zip`），絕不產出超過 500MB 之封包。
3. **申報類別代碼控制**：
   - `1`：初審送核案件
   - `2`：初審補報案件
   - `4`：申覆送核案件（需自動帶入原初審之受理編號 `oldAcptNo`）
   - `5`：申覆補報案件

### 3. 病歷本文（A 類）結構化導出與 PDF 樹狀書籤
- 匯出之 A 類病歷本文優先採用 PDF 格式。
- 順序：病歷首頁 $\rightarrow$ 門診處方箋/藥囑 $\rightarrow$ 門診 SOAP 紀錄單。
- 自動插入 PDF 樹狀書籤（Bookmarks）：清楚標記表單章節，便於審查委員點擊跳轉。
- 預留醫師電子簽章欄位呈現。

### 4. 源頭端品質驗證機制 (Validation-at-Source)
- 11 碼半形英數字嚴格校驗（嚴禁中文檔名、全形字元或空格）。
- 副檔名白名單檢查（嚴禁 `.exe`、裸 `.dcm`；支援 `.pdf`、`.jpg`、`.png`、`.txt`）。
- DICOM 封包必須檢核具備 `DICOMDIR` 引導檔。
- 重複上傳檔名衝突阻斷。
