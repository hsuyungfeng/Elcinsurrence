<objective>
Build the one-shot, LLM-assisted `rule_mapping` precompiled cache per D-04/D-05: for every 醫令代碼 in `payment_rules`/`drug_rules`, determine `(article_location, article_full_text)` either by reusing the CSV's own `payment_text` cell when it already contains substantive review-guideline text (RESEARCH.md Open Question #3 — de-risks ~49% of payment codes), or by prompting the local llama.cpp server (Ornith-1.0-9B) with candidate docx-tree nodes to propose a match. Persist results to a new `rule_mapping` SQLite table. LLM is used only here, at build time — never at query time.

Purpose: This is the third of the three REQ-rule-repository acceptance criteria ("rule_mapping 預編譯快取... 命中率可驗收") and the mechanism that satisfies D-04 (LLM-assisted build) while guaranteeing D-05 (zero LLM at query time).
Output: `llm_client.py` (llama.cpp HTTP wrapper + mandatory smoke test per RESEARCH.md Pitfall 5/Open Question #2), `prompts.py` (candidate-matching prompt templates), `build_mapping.py` (orchestrates the full build: CSV-reuse fast path + LLM fallback path), and `data/db/rules.sqlite3` gains a new `rule_mapping` table populated for all codes.
</objective>
