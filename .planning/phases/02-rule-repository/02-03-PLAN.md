<objective>
Build the custom docx-tree indexer that replaces the (unusable, cloud-only) installed `pageindex` PyPI package. Convert the 11 legacy `.doc` files to `.docx` via LibreOffice headless, then extract a hierarchical tree (node: title, level, path, full_text, table_refs) from all 34 files using `python-docx`'s `iter_inner_content()` for document-order traversal and a regex-based text-pattern hierarchy parser (not style-only detection, which fails on at least 2 confirmed files).

Purpose: This is the second of the three REQ-rule-repository acceptance criteria ("PageIndex 樹狀索引涵蓋...全部文件") and produces the tree JSON that Plan 04's rule_mapping build consumes as its candidate-node source.
Output: `doc_converter.py` (LibreOffice batch conversion), `patterns.py` (regex hierarchy patterns), `extractor.py` (per-file ordered extraction + hierarchy tagging), `tree_builder.py` (orchestrates full 34-file build), `scripts/build_docx_trees.py` (entrypoint that writes tree JSON to `data/db/docx_trees.json` or equivalent), and a green `tests/test_docx_tree_coverage.py` (written in Plan 01, currently red).
</objective>
