建立 `src/elc_audit_engine/generators/appeal_xml.py`：

1. 模組 docstring 說明：本模組為 09-04 Package Builder 的 XML 序列化
   核心，輸入為 `appeal_{流水號}.json`（或呼叫端組裝的 tdata/ddata
   dict），輸出符合官方申復上傳格式的 `ElementTree`；範圍限
   tdata+ddata+pdata（不含 edata 統扣段，2026-08-07 使用者裁示）。

2. `_FULLWIDTH_MAP = {"<": "＜", ">": "＞", "&": "＆", "'": "＇", '"': "＂"}`
   （官方【表8】規則，非 XML entity escaping）。

3. `def _to_fullwidth_specials(text: str) -> str`：以 `str.translate()`
   或逐字元 `str.replace()` 依 `_FULLWIDTH_MAP` 轉換；`text` 為 None
   時回傳空字串（呼叫端已用「無資料不輸出標籤」規則排除 None，
   此函式僅處理已確定要輸出的文字）。

4. `class AppealXmlEncodingError(ValueError)`：Big5 無法編碼時的包裝
   例外，訊息含原始字元與欄位脈絡（不吞掉 `UnicodeEncodeError`，
   而是補充脈絡後重新拋出——保留 `__cause__` 鏈以利除錯）。

5. `def _add_fields(parent: ET.Element, fields: dict[str, object]) -> None`：
   對 `fields` 逐鍵，值為 `None` 或空字串時**跳過**（官方規則：無資料
   不輸出標籤）；否則 `ET.SubElement(parent, key).text = str(value)`。
   **不在此處做全形轉換**——全形轉換只適用於 p8/p9 等自由文字欄位，
   純數字/代碼欄位（如 t1/d1/p1）不應被轉換（避免誤傷非文字資料）。

6. `def build_appeal_xml(tdata: dict, ddata_list: list[dict], *,
   fullwidth_fields: frozenset[str] = frozenset({"p8", "p9"})) -> ET.Element`：
   - `root = ET.Element("outpatient")`
   - `tdata_el = ET.SubElement(root, "tdata")`；呼叫 `_add_fields(tdata_el, tdata)`
   - 對 `ddata_list` 中每個 `entry`（結構：
     `{"dhead": {...}, "dbody": {...}, "pdata_list": [{...}, ...]}`）：
     - `ddata_el = ET.SubElement(root, "ddata")`
     - `dhead_el = ET.SubElement(ddata_el, "dhead")`；`_add_fields(dhead_el, entry["dhead"])`
     - `dbody_el = ET.SubElement(ddata_el, "dbody")`；
       `_add_fields(dbody_el, entry.get("dbody", {}))`
     - 對每個 `pdata` in `entry.get("pdata_list", [])`：
       - `pdata_el = ET.SubElement(dbody_el, "pdata")`
       - 對 `pdata` 逐鍵：若鍵在 `fullwidth_fields` 內，先呼叫
         `_to_fullwidth_specials(str(value))` 再併入要寫入的欄位值，
         其餘鍵直接沿用 `_add_fields` 的空值省略規則
         （可將轉換後的 dict 副本傳入 `_add_fields`，或在迴圈內單獨
         處理 fullwidth 鍵後其餘鍵呼叫 `_add_fields`——擇一皆可，
         但**不得**讓純數字欄位意外被 `_to_fullwidth_specials` 處理）
   - 回傳 `root`

7. `def write_appeal_xml(root: ET.Element, path: str) -> None`：
   - 先以 `ET.tostring(root, encoding="unicode")` 嘗試字串化，
     再以 `.encode("big5")` 手動測試可編碼性；若拋
     `UnicodeEncodeError`，包裝為 `AppealXmlEncodingError` 並帶上
     `from exc` 重新拋出（**不吞、不降級**，符合研究文件 Open
     Question 3 的建議：fail-fast 優於靜默替換）。
   - 確認可編碼後，呼叫
     `ET.ElementTree(root).write(path, encoding="big5", xml_declaration=True)`
     實際寫檔。
   - 寫檔前對 `path` 所在目錄呼叫 `os.makedirs(os.path.dirname(path), exist_ok=True)`。

8. `def draft_json_to_appeal_xml_fields(appeal_json: dict) -> tuple[dict, list[dict]]`：
   把 `render_appeal_json` 輸出的 dict（見本 plan `<interfaces>` 契約）
   轉換為 `build_appeal_xml` 所需的 `(tdata, ddata_list)` 二元組
   （**最小可行版本**：`tdata` 只填 `t2`＝`fee_year_month`，其餘
   t 欄位加總邏輯依 CONTEXT 裁示「留待有真實批次申復需求時再擴充」，
   不在本任務實作；`ddata_list` 為單一元素清單，`dhead`＝
   `{"d1": appeal_json.get("case_class"), "d2": appeal_json.get("case_seq")}`，
   `dbody` 為空 dict（`d3`/`d4` 等欄位本 phase 無對應資料來源，
   依官方規則省略而非猜測填值），`pdata_list` 為單一元素清單，鍵為
   `p1`~`p9`（直接取 `appeal_json["p1_order_seq"]` 等現成鍵，去除
   `pN_` 前綴後對映：`p1`=`p1_order_seq`、`p2`=`p2_order_code`、
   `p3`=`p3_change_seq`、`p4`=`p4_rate`、`p5`=`p5_quantity`、
   `p6`=`p6_points`、`p7`=`p7_attachment`、`p8`=`p8_reason1`、
   `p9`=`p9_reason2`）。
