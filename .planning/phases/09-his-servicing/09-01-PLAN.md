建立 `src/elc_audit_engine/auth.py`，內容為：

1. 模組常數 `API_KEY_HEADER = "X-API-Key"`、`ENV_API_KEYS = "ELC_API_KEYS"`。

2. `class AuthConfigError(RuntimeError)`：設定缺失／格式錯誤（啟動期 fail-fast 用）。
   `class AuthenticationError(Exception)`：認證失敗，屬性 `message`（固定為
   `"認證失敗：缺少或無效的 API key"`）。

3. `parse_api_keys(raw: str) -> dict[str, str]`：解析
   `ELC_API_KEYS="his1:key1,his2:key2"` 格式，回傳 `{key: caller_id}`
   （**以 key 為字典鍵、caller_id 為值**，因為查詢方向是「拿到 key 找呼叫方」）。
   規則：以 `,` 切分項目、以第一個 `:` 切分 caller_id 與 key；兩側 strip；
   caller_id 與 key 皆不得為空（否則拋 `AuthConfigError`）；
   key 長度須 >= 16 字元（弱 key 拋 `AuthConfigError`，訊息不得回顯 key 本體）；
   重複 key 拋 `AuthConfigError`；解析結果為空 dict 時拋 `AuthConfigError`。
   caller_id 須通過 `safe_filename` 白名單同級的校驗——直接呼叫
   `elc_audit_engine.safe_paths.safe_filename(caller_id, "caller_id")`，
   讓 caller_id 可安全進入日誌與檔名（拋 `UnsafeIdentifierError` 時
   轉包為 `AuthConfigError`）。

4. `load_api_keys(raw: str | None = None) -> dict[str, str]`：
   `raw is None` 時讀 `os.environ.get(ENV_API_KEYS)`；為 None 或空字串則拋
   `AuthConfigError("環境變數 ELC_API_KEYS 未設定：本服務會接觸病歷資料，"
   "不得以無認證狀態啟動")`。其餘委派 `parse_api_keys`。

5. `resolve_caller(presented_key: str | None, keys: dict[str, str]) -> str`：
   以 `hmac.compare_digest` 逐一比對，回傳命中的 caller_id；
   **無論命中與否都必須走完全部 key 的比對迴圈**（不可 early-return，
   避免以迴圈次數洩漏資訊）；未命中拋 `AuthenticationError`。
   `presented_key` 為 None／空字串時仍執行一次 dummy `compare_digest`
   後拋 `AuthenticationError`（避免「缺 header」與「錯 key」的耗時差）。
   比對前將兩側 `.encode("utf-8")`。
   **禁止使用 `==` 比對 key**（時序側通道）。

6. `require_api_key(view_func)` decorator（`functools.wraps`）：
   從 `flask.request.headers.get(API_KEY_HEADER)` 取 key，
   呼叫 `resolve_caller`，成功時把 caller_id 寫入 `flask.g.caller_id`
   後執行 view；失敗時拋 `AuthenticationError`（由 server 的 errorhandler
   轉 401）。key 表由 `flask.current_app.config["ELC_API_KEYS"]` 取得
   （由 server 啟動時注入，避免每次請求重讀環境變數）。
