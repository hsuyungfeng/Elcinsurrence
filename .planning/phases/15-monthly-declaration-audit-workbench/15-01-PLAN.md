# Phase 15: 當月申報檔預審與三軌自動化審核工作台 (Monthly Declaration Pre-audit & 3-Track Workbench)

## 階段目標 (Phase Goals)
擴充既有雙軌架構為「三軌自動化審核與申復工作台」：
1. **軌道 1：抽樣事前預審 (Sampling Pre-audit)**：CSV 導入 / 醫令支持度預審 (充分/薄弱/裸奔)。
2. **軌道 2：核減事後申復 (Appeal Post-processing)**：多源證據彙整 / 4 段式申復理由自動生成 / 佐證包與 XML 匯出。
3. **軌道 3：當月申報檔預審 (Monthly Declaration Pre-audit - 新增)**：
   - 支援上傳健保門診申報總檔 `TOTFA.zip`（含 `TOTFA.xml`）。
   - 解析 tdata/ddata/pdata，建立當月申報全量案例索引。
   - 門檻與高風險規則過濾：
     - **診斷碼分析**（主診斷 / 次診斷相容性與適應症）。
     - **醫令單價篩選**：金額 > 350 元之處置/檢驗醫令。
     - **藥令單價篩選**：單價 > 5 元/顆 之高價藥品。
     - **申報規定核對**：比對規則庫支付規範與適應症條件。
   - **SOAP 補強建議與視覺化互動**：
     - 整合 `PageIndex` (樹狀結構化臨床推理/病歷索驥) 進行深度病歷索引與缺口定位。
     - 整合 `answer-me-with-html` 理念生成富有表現力的 HTML 視覺化臨床審查與 SOAP 補強引導卡片。

---

## 計劃分工 (Plan Breakdown)

### Plan 15-01: TOTFA 申報檔解析器與核心資料模型
- **任務**：
  - 支援 `TOTFA.zip` 解壓縮與 Big5 編碼 XML 解析（利用既有 `src/elc_audit_engine/parsers/xml_parser.py` 擴充支援串流/批次處置）。
  - 提取申報案件表頭 (`tdata`)、案件主檔 (`ddata` 診斷碼 d19~d23、就醫日 d9、流水號 d2 等) 與明細處方 (`pdata` 醫令 p4、單價 p10、點數 p11、用法 p13 等)。
  - 資料庫持久化與批次快速查詢（擴充 `CaseStore` 支援申報批次 `MONTHLY-YYYYMM`）。

### Plan 15-02: 高風險與單價門檻篩檢引擎
- **任務**：
  - 實作三級過濾規則：
    1. 醫令價格門檻：處置/檢驗點數 > 350 元。
    2. 藥品價格門檻：藥品單價 > 5 元/顆。
    3. 診斷碼與適應症規範：比對 rules.sqlite3 與 docx tree 條文判定有無給付限制。
  - 產生「當月高風險申報明細表」，依科別、醫師、流水號聚合高風險項目。

### Plan 15-03: PageIndex 臨床推理樹與 SOAP 補強建議生成
- **任務**：
  - 借鏡 `VectifyAI/PageIndex` 理念，構建針對健保申報規範與 SOAP 病歷的結構化索引樹（Reasoning Tree / Guideline Navigation）。
  - 對未附 SOAP 或支持度不足的高風險項目，生成精準補強引導（缺何種檢查數據、缺少何種臨床客觀客體記載）。

### Plan 15-04: Answer-me-with-HTML 視覺化互動介面與工作台整合
- **任務**：
  - 借鏡 `QingYunA/answer-me-with-html` 規格，建立美觀、結構化、可直接於前端互動的 HTML 審核卡片與 SOAP 補強導引面板。
  - 在 Web 介面擴充「當月申報檔預審」分頁，支援拖曳上傳 `TOTFA.zip`、即時過濾（>350元、>5元）、視覺化缺口警示與一鍵匯出補強提示。
