## Narrative Findings (AI reviewer)

### WR-01: App-served inline report HTML is subject to the tightened CSP, contradicting the new "standalone export" docstrings — workbench monthly report renders unstyled with a dead copy button

**File:** `src/elc_audit_engine/monthly_report_html.py:396` (with `:214`, `:10`); `src/elc_audit_engine/services/report_renderer.py:737` (with `:742`, `:463`, `:712`, `:11`); `src/elc_audit_engine/api/security.py:46`

**Issue:** Both modules' HTML is served **inline** by app routes, not as downloads: `GET /api/monthly/batch/<id>/report?format=html` (`src/elc_audit_engine/api/routes/monthly.py:180`), `GET /api/sampling/batch-report` (`src/elc_audit_engine/api/routes/sampling.py:272`), `GET /api/sampling/cases/<id>/preview-html` (`sampling.py:284`), `GET /api/appeal/cases/<id>/preview-html` (`src/elc_audit_engine/api/routes/appeal.py:390`), `GET /api/appeal/batch-report` (`appeal.py:408`). None sets `Content-Disposition`, and every response receives the CSP header via the global `after_request` (security.py:131). Yet the Phase 32.1 notes added to both modules (`report_renderer.py:11`, `monthly_report_html.py:10`: "產出之 HTML 為自包含獨立匯出／下載檔案，供離線檢視，不受應用程式 HTTP CSP 標頭約束") and the comment at security.py:46 ("Python 產生之獨立匯出／下載報表檔不受 app CSP 約束") are false for these routes. Concrete impacts under `style-src 'self'` / `script-src 'self'`:
1. The workbench loads the monthly report into `iframe.srcdoc` (`static/js/workbench.js:1172`, called from the main batch-selection flow at workbench.js:1156/1358/1373). A `srcdoc` iframe **inherits the parent document's CSP**, so the report's `<style>` block (monthly_report_html.py:396) and all 5 inline `style="…"` attributes (:222, :287, :295, :303, :312) are refused — the in-workbench report renders with no styling at all.
2. The `onclick="copySoap(this)"` button (monthly_report_html.py:214) is blocked as inline event-handler content. `copySoap` exists only inside the report's own inline `<script>` (SHARED_SCRIPT from `src/elc_audit_engine/services/report_assets.py:25`), which is itself blocked, so the button is dead in the srcdoc context (and on direct-URL access).
3. Direct browser access to the five routes above is likewise unstyled; the report_renderer pages (`_document`, report_renderer.py:737-742) additionally carry an inline `<script>` (:742) that is blocked — that specific script blocking predates this phase (`script-src 'self'` existed before), but the style blocking is new in 32.1.
The commit message says the 3 retained `onclick="copySoap(this)"` were accepted by the user "於獨立匯出檔" — but the srcdoc and direct-URL consumption paths invalidate that premise for these two modules (the workbench's other report paths use `blob:` + `window.open`, which do not inherit CSP and render fine, which is presumably why this was missed).

**Fix:** Make the two modules' app-served output CSP-clean, e.g. emit the report document referencing external assets and attach a per-route header for the legacy self-contained variant — minimal sketch:

```python
# monthly_report_html.py / report_renderer.py: instead of inlining,
# reference shared assets that the app already serves:
f'<link rel="stylesheet" href="/static/css/report.css">'
...
f'<script src="/static/js/report.js"></script>'   # defines copySoap, lightbox

# and/or, if the self-contained export must stay, scope a per-route CSP
# (security.py) for the five report routes:
#   style-src 'self' 'unsafe-inline'; script-src 'self' 'unsafe-inline'
# documented as an accepted trade-off for report previews only.
```

At minimum, correct the three false claims (report_renderer.py:11, monthly_report_html.py:10, security.py:46) to name the actual app-served routes, so the next reviewer is not misled.
