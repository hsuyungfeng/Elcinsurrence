## Pattern Assignments

### `src/elc_audit_engine/case_store/states.py`（model，純查表）

**Analog:** 自身轉換表 + `IllegalTransitionError`

**W1 修改點——`_TRANSITIONS` 顯式轉換表**（states.py:47-68）：
```python
_TRANSITIONS: dict[str, frozenset[str]] = {
    STATE_IMPORTED: frozenset({STATE_PARSED, STATE_FAILED}),   # ← :48 需加 STATE_APPEALED
    ...
    STATE_APPEALED: frozenset({STATE_SUBMITTED, STATE_FAILED}),
}
```
**只需在 `STATE_IMPORTED` 的目標集合加 `STATE_APPEALED`**（D-01）。其他邊（含
`appealed→submitted`）**不動**（D-02，Phase 10 再做）。

**錯誤語義（D-01 承襲原則，勿改）**——states.py:71-80, 98-119：
```python
class IllegalTransitionError(ValueError):
    """狀態轉換不在顯式轉換表允許的邊內。"""   # :71-80 含 from/to/allowed 三屬性

def can_transition(from_state: str, to_state: str) -> bool:    # :98-108
    if to_state not in ALL_STATES:
        raise UnknownStateError(...)                            # 未知狀態不許回 False
    return to_state in allowed_targets(from_state)

def assert_transition_allowed(from_state, to_state) -> None:    # :111-119
    if not can_transition(from_state, to_state):
        raise IllegalTransitionError(from_state, to_state, allowed_targets(from_state))
```

**⚠️ 語義注意（planner 已裁示）**：`_TRANSITIONS` 是**全局**、無 kind 維度
（states.py:45-46 註解「鍵集合必須恰為 ALL_STATES」）。legalize `imported→appealed`
後 sampling 案件理論上也存在該邊——但 server 端 `transition(…, "appealed")` 唯一呼叫點
在 generate handler（server.py:778），僅 appeal 流程觸發，sampling 案件（走
parsed/reviewing/reviewed 邊）不呼叫之，故**實務無污染**（此確認句已寫入 09.1-01
Task 1 action）；若需更嚴格，於呼叫層依 kind 把關，而非在 states.py 分表（後者會
破壞 :49-51 的遍歷斷言設計）。

## Shared Patterns

### 非法轉換拋例外、不靜默
**Source:** `states.py:71-80, 98-119`
**Apply to:** states.py 轉換表修改 + 相關測試
`IllegalTransitionError`（含 from/to/allowed 三屬性）由 `assert_transition_allowed`
拋出；`transition` 在 store.py:218-219 調用之。**改轉換表不得鬆動此例外語義**。

### 缺欄誠實留空＋warning、不捏造
**Source:** `field_mapping.py:70-74, 144-177`
**Apply to:** W5 submission 轉換層
`_str_or_empty` 統一「None/空→""」；每缺一欄 `warnings.append(欄位名)`。W5 轉換層
補 `case_class/patient_name/orders` 時，案件既有資料無 `id_number` 等欄則留空並
warning，**不得從遮罩值或他欄推測**（承襲 11-01 原則）。

### 認證＋錯誤脫敏
**Source:** `server.py:146-172, 207-227, 230-239`
**Apply to:** generate handler 的 W4/W5 改動
before_request 強制 `X-API-Key`（新增端點預設受保護）；`ApiError`→400/`AuthenticationError`→401；
未處理例外統一 500 脫敏、不迴顯 traceback；入參用 `_clean_str`/`_opt_int` 校驗。

### 前端 authFetch 統一包裝
**Source:** `index.html:334`
**Apply to:** index.html generate 消費段
所有 API 走 `authFetch`；失敗 `alert(data.message)`。W4 適配僅改回應欄位讀取，不換包裝。
