# Plan 17-01: 佐證庫檔案系統規範與 Vault Service 實作

## 目的
實作後台 `EvidenceVaultService`，建立依 `身分證字號-年份月份`（如 `A123625499-2605`）自動歸檔、分類讀取（images/audio/reports/records）與自動解壓 ZIP 之服務與 REST API。

## 任務清單
1. **建立 EvidenceVault 核心模型與 Service (`src/elc_audit_engine/evidence_vault.py`)**:
   - 定義標準目錄路徑 `data/evidence_vault/<vault_key>/`。
   - 支援 `vault_key` 格式校驗（`^[A-Z][0-9]{9}-[0-9]{4}$`，防範路徑穿越攻擊）。
   - 支援自動分類檔案：`images`, `audio`, `reports`, `records`。
   - 支援接收 ZIP 壓縮包並自動解壓入對應子目錄。
   - 支援取得檔案清單與檔案讀取串流（安全限制於該 vault_key 目錄內）。
2. **實作 Vault 相關 API 端點 (`src/elc_audit_engine/api/routes/vault.py`)**:
   - `GET /api/vault/<vault_key>`：取得該病患月份的所有佐證檔案結構與數量。
   - `POST /api/vault/<vault_key>/upload`：上傳檔案或 ZIP 包（multipart/form-data）。
   - `GET /api/vault/<vault_key>/files/<category>/<filename>`：取得檔案內容（供前端播放音訊、顯示影像縮圖或檢視 PDF）。
   - 於 `src/elc_audit_engine/api/app.py` 註冊 Blueprint。
3. **編寫單元測試 (`tests/test_evidence_vault.py`)**:
   - 測試合法/非法 vault_key、檔案上傳與自動分類。
   - 測試 ZIP 自動解壓縮與結構整理。
   - 測試路徑穿越（Path Traversal）安全防禦。
