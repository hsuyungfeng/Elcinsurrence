# Plan 21-02: 批次電子申復 XML 生成（t38/t39 彙總、P6 強制為 0 與全形防護）

## 任務目標
1. 擴展 `src/elc_audit_engine/generators/appeal_xml.py`：
   - 增加批次申復 XML 建構函式 `build_batch_appeal_xml(cases_payload: list[dict]) -> ET.Element`：
     - 在 `<tdata>` 節點中加入 `t38`（申復總件數）與 `t39`（申復總金額點數加總）。
     - 遍歷所有申復案件生成對應的 `<ddata>`，支援每案多筆醫令 `<pdata>`。
     - 若醫令為不申復，強制 `p6` 欄位填 `0`。
     - 針對 `p8`、`p9`（申復理由）落實全形特殊字元置換及長度切分（最多 2,000 中文字）。
     - 輸出保證 Big5 編碼合規（遇無法編碼字元拋出 `AppealXmlEncodingError`）。
2. 新增申復匯出 API 端點：
   - `GET /api/appeal/export-batch-xml`：
     - 抓取目前資料庫中所有申復案件（例如 Stage 3 的 5 案或更多）。
     - 若無案件則回傳 404；若缺少必要欄位回傳 422；成功則回傳 Big5 編碼之 XML 檔案下載（Content-Disposition: attachment）。
3. 前端工作台整合：
   - 在第 3 階申復工作台頂部增加「導出全批次申復 XML」按鈕。
4. 撰寫單元測試：
   - `tests/test_batch_appeal_xml.py`：測試多案申復 XML 結構、t38/t39 加總計算、p6 為 0、Big5 編碼。
