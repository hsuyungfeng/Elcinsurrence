# Plan 22-02: 批次讀取 1000 筆截斷揭露、例外處理不吞錯誤與邊界安全（P1-10, P1-11, P1-12）

## 任務目標
1. **批次查詢 1000 筆截斷透明度揭露（P1-10）**：
   - 審查 `api/routes/sampling.py`、`api/routes/appeal.py`、`case_store/store.py` 中 `limit=1000` 之案件清單與批次端點。
   - 資料庫層以 `COUNT(*)` 取得總筆數，若 `total > limit`，API 回應中明確回傳：
     ```json
     {
       "total": total,
       "returned": len(cases),
       "truncated": true,
       "limit": 1000,
       "cases": [...]
     }
     ```
   - 避免呼叫端誤以為資料庫僅有 1000 筆，落實資訊完全揭露。

2. **規則查詢例外處理透明度（P1-11）**：
   - 在 `sampling.py:176-183`、`appeal.py:268-275` 與核心比對流程中，檢視 `try...except` 區塊。
   - 僅允許對預期的 `RuleRepositoryError` 進行安全降級（如標記 `查無規則` 或回傳 `RuleResult` 預設值）。
   - 禁止使用籠統的 `except Exception:` 吞掉語法錯誤、型別錯誤或非預期的系統錯誤（例如 `NameError`、`KeyError`、`sqlite3.OperationalError`），使其能正常被日誌記錄或向上拋出。

3. **清理 Bare Except 與型別收斂（P1-12）**：
   - 掃除程式庫中所有 `except:`（無型別的 bare except）：
     - `sampling.py:665`、`:671`、`:676`（TOTFA 點數轉型改為 `except (ValueError, TypeError):`）。
     - `appeal.py:366`、`:372`、`:377`（申復點數轉型改為 `except (ValueError, TypeError):`）。
   - 確保所有轉型失敗均有確定日誌或安全的預設值。

4. **測試與驗證**：
   - 撰寫 `tests/test_boundary_safety.py`：
     - 驗證超過 1000 筆案件時的回傳結構含 `truncated: true`。
     - 驗證刻意引發未預期例外時不會被靜默吸收。
     - 驗證字串轉數值異常時正確捕獲指定例外。
