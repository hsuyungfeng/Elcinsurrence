# Plan 22-04: 模組拆分與專屬 Service 層重構（P2-1, P2-2）

## 任務目標
1. **建立專屬 Service 層目錄**：
   - 建立 `src/elc_audit_engine/services/` 模組目錄。
   - 分離 Controller（Flask Blueprint 路由層）與 Service（純業務與資料處理層），解決單一模組超過 700~800 行之維護痛點。

2. **抽離民國（ROC）日期工具庫（P2-2）**：
   - 實作 `src/elc_audit_engine/services/date_utils.py`：
     - 提供標準化的 `roc_to_iso(roc_str: str) -> str`、`iso_to_roc(iso_str: str) -> str`、`roc_year_month(ym_str: str) -> str`。
     - 替換 `sampling.py`、`appeal.py`、`monthly.py`、`parsers/` 中重複撰寫的 8 處日期字串切片邏輯。

3. **拆分 `routes/sampling.py`（P2-1）**：
   - 抽出 `src/elc_audit_engine/services/sampling_service.py`：
     - 包含抽樣演算法（20 隨機 + 10 最高點數立意抽查）、多源證據掛載、案件狀態推進與 TOTFA 解析轉換。
   - `src/elc_audit_engine/api/routes/sampling.py` 瘦身至 250 行以內，專注處理 HTTP 請求校驗、身份驗證與 JSON 封裝。

4. **拆分 `unified_review_report.py`（P2-1, P2-2）**：
   - 抽出 `src/elc_audit_engine/services/report_renderer.py`：
     - 模組化 HTML 組裝流程、CSS 樣式表與前端動態折疊腳本。
     - 消除與 `monthly_report_html.py` 之間的重複樣式定義。
     - 修正 onclick 事件注入疑慮（P1-18），改以合規之 data 屬性與安全字串渲染。

5. **測試與驗證**：
   - 執行既有全套抽樣與報告測試（`test_sampling_api.py`、`test_phase20_stage_batch.py`、`test_monthly_report_html.py` 等）。
   - 確保所有 API 端點路徑、參數與回應格式 100% 向後相容，零功能倒退。
