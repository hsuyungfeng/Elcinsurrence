## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Two-tier milestone roadmap breaks gsd-sdk phase parsing | progress.md's original roadmap nested M1-M8 milestones inside a single "Phase 1" section. `gsd-sdk query init.plan-phase` returned `phase_found: false` / `phases.list` returned empty against that shape — it only recognizes the flat `### Phase N: Name` format with Goal/Depends on/Requirements/Success Criteria/Plans fields. | advisory | ROADMAP.md was rewritten to one GSD Phase per former milestone (Phase 1-8 = M1-M8, Phase 9 = HIS integration). If ROADMAP.md is ever hand-edited again, keep every phase in the flat `### Phase N: Name` format — do not reintroduce nested milestones-within-a-phase. |
| `uv run pytest` silently resolves a global pytest install | Declaring test deps only via `dependencies = [...]` (or omitting a dev-group entirely) lets `uv run pytest` fall through to any pre-existing global `pytest` on `$PATH` instead of failing — this passed locally by accident (a global pytest happened to exist) and would have failed non-deterministically on a clean machine/CI. | blocking | Any pyproject.toml touched in future phases must declare test-only deps via `[dependency-groups] dev = [...]` (PEP 735 / current uv convention, NOT the deprecated `[tool.uv.dev-dependencies]`), and verify with `uv run which pytest` resolving inside `.venv/`, not a global path. |

**Severity values:** `blocking` — resuming agent must pass understanding check before proceeding. `advisory` — important context, does not gate resumption.
