## Cross-Phase Integration Findings

Spawned `gsd-integration-checker` to trace Phase 12→14 wiring, Phase 12→appeal.py wiring, full E2E flow, route consistency, and residual stubs/TODOs. All findings below were independently re-verified against the live source by the orchestrator (not taken solely on the subagent's word).

1. **Phase 12 → Phase 14 wiring — GAP (blocker).** `server.py:1130-1154` (`generate_evidence_packet_print`): the route derives its `attachment_store.list_attachments()` lookup key from `case_id` (via `safe_filename(case_id)`), while Phase 12's `attachment_store` keys all storage by `case_seq` (its own routes at `server.py:1027,1051` take `case_seq` as the literal path parameter; `save_attachment`/`list_attachments`/`delete_attachment` all build `case_dir` from `case_seq`). `case_id` and `case_seq` are separate, independently-populated columns (`case_store/store.py:36,39`; `server.py:337-339`), and `case_seq` is nullable. The case record is already fetched at line 1136 (`case.case_seq` is available) but the code reuses `safe_case` (from `case_id`) at line 1154 instead. **Confirmed by direct read — this is a real bug, not a hypothetical.**

2. **Phase 12 → appeal.py wiring — verified.** `appeal.py:357-359`'s dynamic `has_attachment` lookup (via `attachment_store.has_attachment(record.case_seq, record.order_seq)`) only fires when the caller passes `None`. Traced real call path at `server.py:878` — the frontend omitting the field propagates `None` through correctly. No bypass path found.

3. **E2E flow — broken at step 4/4.** Upload (step 1, OK) → appeal draft generation with correct dynamic flag (step 2, OK) → deduction print, independent path (step 3, OK) → evidence packet print (step 4, **broken** — attachment silently omitted whenever `case_id != case_seq`).

4. **Route consistency — verified, no inconsistency.** All 5 new endpoints across the 3 phases are correctly registered in `_AUTH_EXEMPT_ENDPOINTS`, none in `_AUDIT_EXEMPT_ENDPOINTS`, so all fall through to the same PHI-free audit hook. Consistent pattern.

5. **Stubs/TODOs — none blocking.** Only the already-tracked ODT placeholder (out of scope, tracked separately) and one cosmetic stray dev comment at `server.py:1165`.

## Fix Applied

Fixed inline during this audit (commit `3f7f097`). In `generate_evidence_packet_print` (`server.py`), the attachment lookup now reads:
```python
attachment_key = case.case_seq or safe_case
...
for a in attachment_store.list_attachments(attachment_key)
```
This matches the key space Phase 12 actually writes to, falling back to the `case_id`-derived key only when `case.case_seq` is empty or `None`. Two regression tests added to `tests/test_evidence_packet_pdf.py`:
- `test_api_evidence_packet_looks_up_attachments_by_case_seq` — asserts lookup uses `case.case_seq` when present
- `test_api_evidence_packet_falls_back_to_case_id_when_case_seq_missing` — asserts fallback behavior when `case_seq` is `None`

Also removed a stray internal-monologue dev comment at the same call site (cosmetic, noted in Check 4 above).
