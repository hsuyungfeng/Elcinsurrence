要將健保署的「電子抽審」與「電子申覆」功能整合接入如 doctor-toolbox 般的雲端 HIS 系統，必須解決**雲端架構與地端健保 VPN 封閉網路（需讀卡機與 SAM 卡）的橋接問題**，並嚴格遵循健保署的檔案格式與傳輸規範。

以下為雲端 HIS 系統整合健保電子抽審與申覆的完整技術與實務實作指南：

### 一、 系統整合架構設計 (雲端與地端橋接)

由於健保署的傳輸需要使用實體的健保卡專用讀卡機（置入安全模組卡 SAM 卡）進行加密與簽章，且必須在特定的健保 VPN 網域內執行，雲端 HIS 無法「直接」把資料丟給健保署。因此，系統架構通常設計如下：

1. **雲端 HIS 處理層**：在雲端完成抽樣名單的比對、病歷資料打包（PDF、TXT 等）、醫療影像（DICOM）整理，以及申覆 XML 檔案的生成。
2. **地端代理程式 (Local Agent)**：在診所本地端的電腦（已連上 VPN 並插有 SAM 卡）安裝一支中介程式（或稱 Agent）。雲端 HIS 將打包好的檔案推播或讓地端 Agent 下載。
3. **呼叫 NHI_EII API**：地端 Agent 透過健保署提供的「醫療資料傳輸共通介面 API (NHI_EIIAPI.DLL)」，呼叫 `NHI_SendA` 或 `NHI_SendB` 函式，由本地硬體完成簽章加密後上傳至健保署 IDC。

### 二、 電子抽審 (病歷與影像上傳) 技術規範

雲端 HIS 在自動化打包抽審案件時，必須嚴格遵守以下格式與命名規範，否則會遭到系統退件或取消電子送審資格：

1. **檔案格式限制**：
   * **文字病歷**：支援 WORD、TXT、HTML、PDF、電子病歷 XML 格式。嚴禁上傳 EXE、ZIP、RAR 等壓縮檔。
   * **醫療影像**：必須是 DICOM v3.0 格式，且**必須以「DICOMDIR」這個檔案為引導檔進行上傳**。若非 DICOM，可接受 GIF, JPEG, PICT, TIFF, BMP 等圖檔。
2. **檔案命名編碼規則**：
   雲端系統在產製檔案時，檔名必須由程式自動命名為：**第一階層代碼（2碼）+ 第二階層代碼（1碼）+ 案件分類代碼（2碼）+ 案件流水號（6碼）**。若有多張影像檔，檔名最後須加上數字編號區隔以防覆蓋（如：13B190123451 與 13B190123452）。
3. **上傳操作邏輯**：一筆個案的「所有」送審電子檔案必須全部加入後一次性執行上傳，絕對禁止分開多次上傳。

### 三、 電子申覆作業 (XML 生成) 技術規範

若對抽審核減有異議，雲端 HIS 須能自動產製「電子申覆 XML」檔案。HIS 開發時須對應以下關鍵欄位：

* **P3 (改支序號)**：須精準填報健保署核算資料醫令改支檔案（第九欄位）中的變更代碼。
* **P4 / P5 (成數/數量受理)**：院所自填的申覆訴求值。
* **P6 (點數受理)**：申覆點數。若該筆案件中有「不申覆」的醫令，**此欄位必須強制填 0**，不可漏報。
* **p7 (申覆檔案連結)**：若填寫 `Y`，代表將透過電子化審查系統 (PACS) 上傳新事證，系統會自動予以連結。
* **p8 / p9 (申覆理由)**：長文字欄位，支援最多 2,000 個中文字。
* **t38 / t39 (申覆總件數/總金額)**：同次上傳中不同診別的申覆件數與金額加總。

### 四、 API 介接與上傳實作參數

地端 Agent 在呼叫「醫療資料傳輸共通介面 API」進行上傳時，需使用正確的 `sTypeCode`（作業種類代號）：

* **`00`**：電子化專業審查系統使用（通常用於單筆或病歷影像上傳）。
* **`15`**：費用抽審 XML 格式批次上傳。
* **`07`**：醫療費用電子申復資料。
* **`09`**：預檢醫療費用電子申復資料（上傳前可先進行預檢）。

使用 `NHI_SendA` 或 `NHI_SendB` 函式上傳後，系統會回傳 `sLocal_ID` 與 `sNHI_ID`（或執行編號），HIS 可利用這些編號呼叫 `NHI_Query` 來追蹤檔案是否已成功進入「A12: 檔案已就緒」或「A99: 已傳送完成」的狀態。

### 五、 院所行政前置申請作業

在雲端 HIS 開發完成並準備為診所導入時，診所端必須先完成以下行政程序，系統才能正式發揮作用：

1. **VPN 權限開通**：以醫事機構負責人憑證登入 VPN，至「用戶作業申請」勾選「電子化專業審查系統」提出申請。
2. **試傳與確認**：申請通過後，HIS 廠商需協助診所進行「試傳作業」，試傳 2 至 5 筆虛擬測試資料，並於上傳成功 2 小時後以電話向所屬健保分區業務組窗口確認。
3. **雙軌並行至單軌**：初期需經歷電子與紙本並行的「雙軌送審」階段，待健保署確認電子檔案的影像品質清晰、無缺頁模糊後，方得全面改採單軌（無紙化）送審。若上傳品質不良且累計輔導兩次未改善，會被取消電子送審資格半年。    針對以上研究艮建議與計畫 並搜尋原本紙本範本

你的研究方向是正確的，但若是要做成 **Doctor Toolbox 類型雲端 HIS 整合健保電子抽審/電子申覆** 的研究計畫，我建議除了技術架構外，再加入**現行紙本作業流程分析、紙本表單數位化對照、系統流程設計及導入計畫**，會比較完整，也符合資訊系統研究（IS）、醫療資訊（Medical Informatics）及政府資訊系統整合的撰寫方式。
